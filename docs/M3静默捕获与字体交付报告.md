# M3 交付报告：静默捕获 + 字体选择

> 日期：2026-09-18
> 目标：解决 M2 遗留的「划词弹窗反而打断阅读」问题，并加上字体选择。
> 结论：**M3 完成，全链路自检 PASS（exit 0）。**

---

## 一、为什么做这件事

M2 做完划词新建之后，我发现一个问题：**每摘一次词就弹一个窗口，本质上只是把「分屏的繁杂」换成了「窗口的繁杂」**。你的原始痛点是"看文章时不想被工具打断"，而弹窗恰恰是最强的那种打断——注意力被从文章上拽走，还得处理新窗口。

所以 M3 的核心不是加功能，是**改掉 M2 的交互**。

---

## 二、静默捕获（M3 主项）

### 新的工作流

```
读文章 → 选中一段 → ⌥⌘E
        ↓
   屏幕底部弹一个胶囊：「✓ 已存入今日笔记 · 第 3 条」
   （不抢焦点，1.9 秒后自动消失）
        ↓
   继续读，不受打扰
        ↓
读完 → ⌥⌘T 打开今日笔记，统一整理
```

### 今日笔记长这样

同一个文件 `2026-09-18 今日笔记.md`，每次捕获追加一个小节：

```markdown
## 10:57 · 测试文章标题

> 测试摘录第一行
> 测试摘录第二行

[原文链接](https://example.com/article-a)
```

按时间顺序累积，读完整理时可读性比一堆散落的窗口好得多。

### 两个关键实现细节

**① 追加走两条路径，避免和编辑器打架**

| 情况 | 路径 |
|---|---|
| 今日笔记**没打开**（读文章时的常态） | 直接原子写文件 |
| 今日笔记**已打开**（正在整理时） | 通过 JS 让编辑器 `insertBlocks` 追加，再靠它自己的自动保存落盘 |

如果两条路径混用会互相覆盖——编辑器内存里的文档和磁盘上的文件会不一致。所以按"是否打开"分流。

**② 提示胶囊刻意不抢焦点**

用 `.nonactivatingPanel` + `orderFrontRegardless()`，自检里专门验了这一点：

```
[selftest] 提示面板可见 = true，前台 App DSH Desktop → DSH Desktop ✅
```

如果这里抢焦点，等于绕了一圈又回到"打断阅读"。胶囊可以点击 -> 直接打开今日笔记，想马上看的时候也顺手。

### 可选回旧行为

设置面板 → 划词捕获 → 「弹出新窗口」。边读边展开写的情况仍然可用。

## 三、字体选择

设置面板新增「正文字体」下拉，8 个选项（全部**实测存在于本机**，不是拍脑袋列的）：

| 选项 | 字体 |
|---|---|
| 系统默认 | `-apple-system` + 苹方 |
| 苹方 · 黑体 | PingFang SC |
| 黑体 | Heiti SC |
| 宋体 | Songti SC |
| 楷体 | Kaiti SC |
| 圆体 | Yuanti SC |
| 冬青黑体 | Hiragino Sans GB |
| 等宽 | Menlo |

字号滑杆范围从 12–24 扩到 **12–26**，并带**实时预览**（中英文各一行）。

### 顺带修掉一个一直没发现的 bug 🔴

写测试时才发现：**字号设置其实从 M1 起就一直没生效过**。

原因：BlockNote 把 `font-family` **和 `font-size` 都写在 `.bn-default-styles` 上**：

```css
.bn-default-styles {
  font-size: 16px;
  font-family: Inter, SF Pro Display, -apple-system, ...;
}
```

我之前只覆盖了 `.bn-editor`，选择器权重相同但 BlockNote 的样式在运行时后注入，所以我的一直被盖掉。

**修复**（同时覆盖两者 + `!important`）：

```css
.bn-default-styles,
.bn-editor {
  font-family: var(--fn-font-family) !important;
  font-size: var(--fn-font-size) !important;
}
/* 代码保持等宽，不受正文字体影响 */
.bn-inline-content code,
.bn-block-content[data-content-type="codeBlock"] {
  font-family: Menlo, "PingFang SC", monospace !important;
}
```

自检里加了**读 WebKit 计算样式**的断言，把这个问题钉死：

```
[selftest] 编辑器计算样式 = {"family":"\"Kaiti SC\", STKaiti, serif","size":"21px"}
```

> 这个 bug 值得单独说一句：如果只靠肉眼看，很容易觉得"好像变了又好像没变"。
> 只有把**计算后的实际样式**读出来对比，才能确定它真的生效了。

## 八、已知限制

| # | 限制 | 说明 |
|---|---|---|
| L-1 | 今日笔记靠文件名识别 | `2026-09-18 今日笔记.md`，手动改名后就不认了 |
| L-2 | 静默追加不带"撤销" | 存错了要自己去今日笔记里删。胶囊没有 undo 入口 |
| L-3 | 字体是全局设置 | 不能每篇笔记单独设字体（透明度/主题是每篇独立的） |
| L-4 | 提示胶囊位置固定 | 屏幕底部居中，不可拖动 |
| L-5 | 长摘录会整段塞进今日笔记 | 没有自动截断或"仅存要点"的选项 |

## 九、M4 候选

按对「读文章」这个场景的价值排序：

1. **今日笔记的整理视图** —— 现在是纯追加的流水账。可以做一个「未整理 / 已归档」两栏，读完随手把摘录拖进对应的主题笔记。**这是"读完再一起整理"这个流程真正缺的一环。**
2. **摘录去重** —— 同一段选中两次会存两条
3. **来源回访** —— 点笔记里的来源链接跳回原文，并且能定位到原位置
4. **AI 摘要** —— 读完一篇文章，一键把今日笔记里这篇的所有摘录合成一段总结
5. **搜索升级** —— 分词 + 拼音首字母（现在上千条会有点慢）
6. **图标设计 + iCloud / Git 同步**
