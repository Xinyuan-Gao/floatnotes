# 图标交付报告

> 日期：2026-09-18
> 内容：App 图标 + 菜单栏图标，风格为「渐变底 + 悬浮卡片」。

**先看这张图**：`icon-preview.png`（同一个图标在浅色/深色背景下、16/32/64/128/256 五个尺寸的对照）。

---

## 一、做法：代码画，不用 AI 生图

图标是用 Core Graphics **画出来的**（`tools/IconGenerator.swift`），不是 AI 生成的。理由：

| | 代码渲染 | AI 生图 |
|---|---|---|
| 尺寸适配 | 每个尺寸精确重绘 | 只能缩放，小尺寸糊 |
| 可复现 | 改常量即可重出 | 每次结果不同 |
| 精确度 | 圆角、比例完全可控 | 容易出毛边、比例失真 |
| 小尺寸优化 | 可单独走简化版 | 做不到 |

**关键点：小尺寸走的是另一套画法。** 16px 下画三条细线会糊成一团，所以 ≤32px 时自动切换成「两条更粗的线 + 卡片放大」的简化版。像素采样验证过简化版在 16px 下中心亮度 246，仍然清晰可辨。

---

## 二、设计

- **底**：824×824 的圆角方块（macOS 惯例的 9.77% 留白 + 22.37% 圆角），蓝紫渐变 —— 和悬浮球用的是同一组颜色，视觉上是同一套系统
- **前景**：一张白色卡片，下方带柔和投影，做出「浮起来」的感觉
- **卡片内容**：三条文字线，第一条用强调色（像标题），最后一条短一截

配色取自悬浮球：靛蓝 `rgb(74,96,252)` → 紫 `rgb(148,62,245)`。实测渲染出来左上 225°、右下 257°，色相过渡正确。

菜单栏图标是同一套语言的单色版（`isTemplate`，自动适配深浅色和选中态）：卡片轮廓 + 三条线，第一条略粗。

---

## 三、我能"看"图吗？——用像素采样代替人眼

这个模型读不了图片，所以我写了个验证脚本 `tools/verify-icon.swift`，**用采样代替目视**，检查：

```
【1024×1024 主图】
  ✓ 圆角外透明：左上角 rgba=(0, 0, 0, 0)
  ✓ 卡片中心为白：中心 rgb=(250,250,255) α=255
  ✓ 圆角内无透明空洞：检查了 7 个点，全部不透明
  ✓ 左上偏靛蓝：最饱和 rgb=(121,153,253) 色相=225° 饱和=52%
  ✓ 右下偏紫：最饱和 rgb=(134,102,209) 色相=257° 饱和=51%
  ✓ 卡片上有强调色标题线：rgb=(147,171,252)
  ✓ 卡片下方有投影（悬浮感）
【16×16 小尺寸】
  ✓ 中心可辨识（偏亮）：亮度=246
  ✓ 外圈透明
  ✓ 底色仍是蓝紫：色相=248°
PASS ✅
```

外加两项端到端检查：

- **菜单栏图标结构**（`--dump-icons` 导出后采样）：不是空白、不是实心方块、四角透明、有左侧描边、内部有线条结构
- **macOS 是否真的认这个图标**：用 `NSWorkspace.icon(forFile:)` 取回系统展示的图标，采样发现**蓝紫色像素占 45.3%** —— 系统通用图标是灰度的，不可能有蓝紫，所以确认已采用

## 四、这套验证抓到一个真 bug 🔴

第一轮验证报了三处不符，我一开始以为是自己脚本的坐标系写错了（`NSBitmapImageRep.colorAt` 用**左上原点**，和 Core Graphics 的左下原点相反 —— 这确实也错了，一并修了）。

但改完坐标系后，"左上偏靛蓝"仍然不达标。于是专门写了个空洞探测：

```
检查圆角内部是否有透明空洞：
  ✗ (150,130) α=0   ← 透明空洞！
  ✗ (200,150) α=44  ← 透明空洞！
  ✗ (260,130) α=47  ← 透明空洞！
  ✗ (140,200) α=37  ← 透明空洞！
  ✗ (120,260) α=29  ← 透明空洞！
发现 5 个空洞
```

**根因**：`CGContext.drawLinearGradient` 在默认 options 下**只绘制起点和终点之间的区域**，之外完全不画。我的渐变轴是从左上偏中斜向右下，左上角那片正好落在「起点之前」——于是整块没上色，留下透明空洞。

**这在成品上就是图标左上角缺一块。** 而且它长得很像"正常的圆角"，肉眼扫过去很可能不会发现。

**修复**：

```swift
ctx.drawLinearGradient(grad, start: ..., end: ...,
                       options: [.drawsBeforeStartLocation,   // ★
                                 .drawsAfterEndLocation])     // ★
```

同时把顶部高光从 20% 降到 12%（原来把颜色洗得发灰），渐变两端各加一点饱和度。修完饱和度从 44% 提到 52%，空洞归零。

## 五、怎么重新生成

```bash
cd floatnotes
./tools/make-icon.sh          # 渲染 10 个尺寸 → iconutil 打包成 Resources/AppIcon.icns

# 验证（需要 iconset，脚本会自己生成）
swiftc -O tools/IconGenerator.swift -o /tmp/gen && /tmp/gen /tmp/check
swiftc -O tools/verify-icon.swift   -o /tmp/verify && /tmp/verify /tmp/check
```

`build.sh` 里已经接好了：**如果 `Resources/AppIcon.icns` 不存在会自动生成**，所以新克隆下来直接 `./build.sh` 也能出图标。

## 七、可能需要你判断的地方

我看不到成品，以下几点只能你来看：

1. **整体观感** —— 渐变会不会太亮/太暗？卡片大小合适吗？
2. **16px 下能否一眼认出** —— 我验了"中心偏亮、底色仍是蓝紫"，但够不够辨识得你说了算
3. **菜单栏图标的粗细** —— 在深色菜单栏 / 浅色菜单栏下是否都清楚
4. 如果想调，改 `IconGenerator.swift` 顶部的几个常量（渐变色、卡片比例、圆角比例、线条粗细）重跑 `make-icon.sh` 即可，一分钟的事

# 附录：图标"看不到"的排查记录

> 追加于同日。用户反馈「我的应用程序没有这个图标」。

## 排查过程

先确认图标本身有没有问题：

| 检查 | 结果 |
|---|---|
| `.icns` 文件头 | ✅ 合法的 `icns` 魔数，声明长度 = 实际长度 |
| `.icns` 内含尺寸 | ✅ 10 个表述全在（16/32/128/256/512/1024 + 各自的 @2x） |
| `CFBundleIconFile` | ✅ = `AppIcon`，指向的文件确实存在 |
| 系统上有几份 | ✅ 只有一份，排除"看的是旧副本" |
| `NSWorkspace.icon(forFile:)` | ✅ 蓝紫像素 45.3%，说明系统确实认 |

**所以图标资源完全正确，问题在别处。**

## 真正的原因（两个叠在一起）

### 1. 这个 App「本来就不会有 Dock 图标」

根因在 `Info.plist` 里的这一行：

```xml
<key>LSUIElement</key>
<true/>
```

`LSUIElement = true` 让 App 的激活策略变成 **`.accessory`** —— 不出现在程序坞，也不进 ⌘Tab。这是我 M0 为了「点击笔记窗口不打断阅读」故意设的，形态上是纯菜单栏 App（类似 Raycast、Bartender）。

**但这是我自己做的设计决定，并没有跟你确认过。** 你的预期显然是"像个正常 App 一样有图标"，这个预期是合理的。

实测确认：

```
悬浮笔记: 激活策略 = accessory → 【没有】Dock 图标、不进 ⌘Tab（菜单栏 App）
```

### 2. App 埋在很深的目录里 + 图标缓存

App 原本只在 `2026.09.18-悬浮笔记MacApp/dist/` 下，不在 `/Applications`，所以在启动台里根本找不到。而且这个 bundle 在同一路径下被重建过十几次，Finder / LaunchServices 的图标缓存是旧状态。

## 修复

### ① 做成可切换的开关，默认打开

新增设置项「**在程序坞中显示图标**」（默认 **开**）：

```swift
// main.swift
app.setActivationPolicy(Settings.shared.showInDock ? .regular : .accessory)
```

- **开** → `.regular`：有 Dock 图标，也能用 ⌘Tab 切过来
- **关** → `.accessory`：纯菜单栏 App，不占 Dock

菜单栏和设置面板里都能随时切换，改完立即生效（不用重启）。

### ② 验证「不打断阅读」这个特性没有丢 ⭐

这是改激活策略最需要担心的地方——`.regular` 的 App 通常会因为窗口被点击而抢到前台。

**实测结果：不受影响。**

```
[selftest] S3 焦点: 前=访达 后=访达 → 未打断 ✅
[selftest] 激活策略 = regular（有 Dock 图标）；S3 焦点检查是在此策略下做的
```

原因：「点击笔记窗口不抢焦点」靠的是面板本身的 `.nonactivatingPanel` 样式，**和 App 的激活策略是两件独立的事**。自检里现在会把当前策略一起打出来，以后换策略也能立刻看出有没有影响。

### ③ 装到正规位置 + 清缓存

```bash
ditto "dist/悬浮笔记.app" "/Applications/悬浮笔记.app"
lsregister -f "/Applications/悬浮笔记.app"     # 强制重新登记
killall Dock                                   # 清 Dock 图标缓存（会自动重启）
```

顺带的好处：装到 `/Applications` 之后，**「开机自动启动」也能真正生效了**（`SMAppService` 要求 App 位于 `/Applications`）。
