## 二、划词新建长什么样

在浏览器里选中两行字，按 `⌥⌘E`，新窗口里直接出现：

```markdown
> 深度学习需要大量数据
> 第二行内容

摘自 [Attention Is All You Need](https://arxiv.org/abs/1706.03762) · via Safari · 2026-09-18 10:52
```

笔记文件名自动取来源标题：`摘录-Attention Is All You Need.md`（做了文件名合法化，`/ : * ?` 之类会被替换）。

**技术上怎么拿到这些信息：**

1. **主路径 —— macOS 辅助功能 API（AXUIElement）**
   - 从系统级 `AXFocusedUIElement` 拿到当前焦点元素
   - `AXSelectedText` 取选中文字
   - **沿父链往上走最多 10 层**找 `AXDocument` / `AXURL`，拿到浏览器 / 阅读器暴露的文档 URL
   - 沿父链找 `AXTitle` 拿窗口标题
2. **兜底 —— 模拟 ⌘C + 读剪贴板**
   - AX 拿不到文字时启用
   - **会先把用户原本的剪贴板内容完整备份，读完立刻还原**（包括富文本类型），不污染剪贴板
3. **权限** —— 未授权时弹出说明并一键跳到「系统设置 › 隐私与安全性 › 辅助功能」

## 四、M2 踩的坑（都已解决）

### 坑 1 · FSEvents 回调直接段错误 🔴 最严重

FSEvents 的 C 回调里，我一开始这么写：

```swift
// 错误：把它当成 NSArray
let paths = unsafeBitCast(eventPaths, to: NSArray.self) as? [String] ?? []
```

但**没有设置 `kFSEventStreamCreateFlagUseCFTypes` 时，`eventPaths` 是 C 数组 `char*[n]`**，不是 CFArray。这个错误转换直接 `EXC_BAD_ACCESS` 崩溃。

崩溃报告很明确：

```
Exception Type:  EXC_BAD_ACCESS (SIGSEGV)
Thread 2 Crashed:
  libobjc.A.dylib   objc_msgSend
  Foundation        Array._conditionallyBridgeFromObjectiveC
  FloatNotes        closure #1 in NoteWatcher.start(onExternalChange:)
  FSEvents          implementation_callback_rpc
```

**正确写法**（按指针解引用）：

```swift
let cPaths = raw.assumingMemoryBound(to: UnsafeMutablePointer<CChar>?.self)
for i in 0..<count {
    if let p = cPaths[i] { out.append(String(cString: p)) }
}
```

> 附带一个小坑：这个函数放在 `NoteWatcher` 的静态方法里，闭包内写 `Self.decodePaths` 会报
> 「C function pointer cannot be formed from a closure that captures dynamic Self type」，
> 必须写具体的类型名 `NoteWatcher.decodePaths`。

### 坑 2 · `blocksToHTMLLossy` 是同步方法

```js
// 错误：它不是 async
editor.blocksToHTMLLossy(editor.document).then(v => ...)
// → TypeError: ...then is not a function
```

BlockNote 里 `blocksToMarkdownLossy` / `tryParseMarkdownToBlocks` 是 async，但 **`blocksToHTMLLossy` 是同步返回字符串**的。改用 async IIFE 包一层即可。

### 坑 3 · 局部变量遮蔽同名方法

```swift
let snippet = bodyHit.map { snippet(around: $0, ...) }   // ❌ 遮蔽了静态方法 snippet
```
编译报「cannot call value of non-function type 'String'」。改名即可。

### 顺带修的一个数据安全问题

外部同步最初是无条件刷新。我加了一道**防覆盖保护**：如果本地还有防抖窗口内没落盘的输入，就**跳过这次外部刷新**，绝不覆盖用户正在打的内容。自检里能看到它真的触发了：

```
[sync] 跳过（有未保存输入）：外部同步测试
```

## 七、已知限制

| # | 限制 | 说明 |
|---|---|---|
| L-1 | 划词依赖辅助功能权限 | 未授权时只能新建空笔记，会弹窗引导 |
| L-2 | 个别 App 不暴露 `AXDocument` | 这类 App 只能拿到窗口标题，拿不到 URL（会优雅降级） |
| L-3 | 外部同步不弹冲突提示 | 有未保存输入时直接跳过，不做三向合并。对单人使用够用，多人协作场景不够 |
| L-4 | 搜索是子串匹配 | 没有分词、没有拼音首字母、没有模糊匹配；笔记上千条后可能需要换索引 |
| L-5 | 附件回收不会自动跑 | 需要手动从菜单触发（避免误删还没保存引用的图） |
| L-6 | Markdown 首次保存规范化列表符号 | `- ` → `* `，一次性、之后幂等（M1 已知） |

## 八、下一步（M3 候选）

按你的实际场景排的优先级：

1. **划词后不打断阅读** —— 现在 `⌥⌘E` 会弹出一个新窗口抢走注意力。可以改成「先静默存进今日笔记，不弹窗」，读完再一起整理。**这条可能比加功能更值钱。**
2. **来源锚定与回访** —— 笔记里记住来源，能一键跳回原文位置
3. **每日笔记 / 收件箱模式** —— 所有划词默认进「今天」这一篇，而不是各开一个窗口
4. **搜索升级** —— 分词 + 拼音首字母
5. **iCloud / Git 同步**
6. **AI 能力** —— 选中一段 → 让模型总结/追问
